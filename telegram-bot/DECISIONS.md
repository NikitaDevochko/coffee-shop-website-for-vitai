# Решения по боту

## B-D1. Long polling вместо вебхука
**Решение:** бот сам опрашивает API сайта.
**Почему:** заявки живут в FastAPI, инициатор опроса — бот: не нужен публичный HTTPS-домен для бота,
не нужно вебхук-согласование, перезапуск не теряет данные (курсор в БД).
Цена: задержка до `POLL_INTERVAL_SECONDS` (5 c) и лишние запросы — при нашем объёме незначительны.

## B-D2. Не читать БД сайта напрямую
**Решение:** только HTTP `GET /api/leads`.
**Почему:** подпроекты остаются независимыми (можно развести по хостингам и репозиториям),
схема БД сайта не протекает в бота. Цена: бот зависит от доступности API — закрыто ретраями и курсором.

## B-D3. Свой стейт доставки
**Решение:** локальный SQLite с `last_id` и журналом доставок.
**Почему:** Telegram не даёт идемпотентности; журнал даёт защиту от дублей при рестарте и отчёт о сбоях.

## B-D4. Один чат менеджеров вместо личных сообщений
**Решение:** `TELEGRAM_CHAT_ID` (группа), а не рассылка конкретным людям.
**Почему:** бриф требует уведомить менеджера; состав команды меняется без правок кода.
