# Этапы разработки сайта

Этапы 0–7, с оценкой в часах и проверяемым результатом. Общий бюджет брифа — 4–6 часов
чистой работы.

## Этап 0. Подготовка (0,25 ч)
- Репозиторий, ветки, `.gitignore`, линтеры/форматтеры (ruff, eslint, prettier).
- Проверить актуальные версии Next.js/FastAPI и API Telegram Bot (дата-чувствительно).
- **Результат:** пустой проект собирается, коммит «chore: bootstrap».
- **Что делает ИИ:** генерация конфигов и CI-скелета; **что вручную:** выбор версий и хостинга.

## Этап 1. Каркас фронта и дизайн-система (0,75 ч)
1.1 `create-next-app` (TypeScript, App Router, Tailwind), структура `web/`.
1.2 `next.config.ts`: домены изображений, заголовки безопасности.
1.3 Токены: палитра (в брифе есть фирменный тёмно-зелёный `#1D5C4A`), типографика (кириллица!), сетка, `Reveal`/`Button`/`Section`.
1.4 Подбор фото на Unsplash/Pexels, локальная оптимизация (`next/image`), атрибуция.
- **Результат:** страница со «скелетом» секций и реальными шрифтами/цветами.
- **Риск:** «типовой сгенерированный лендинг». Митигация: сначала 2–3 разных визуальных направления, осознанный выбор, а не первый ответ ИИ.

## Этап 2. Контент и вёрстка лендинга (1,5 ч)
2.1 `lib/content/*.ts` — единый источник фактов (ассортимент, цены, адрес, часы).
2.2 Секции: Hero → Почему свежесть → Ассортимент → Подписка → Доставка и самовывоз → Контакты → Форма.
2.3 Секция формы с якорем `#lead`, все CTA ведут в неё.
2.4 Анимации: появление секций, бегущая строка; отключение при `prefers-reduced-motion`.
2.5 Экран благодарности.
- **Результат:** полный лендинг с рабочей вёрсткой, форма ещё не отправляет.
- **Проверка:** mobile-first 360–430 px, отсутствие горизонтального скролла, контраст ≥ 4.5:1.

## Этап 3. Форма и бэкенд (1,5 ч)
3.1 Модели и схемы заявки, миграция SQLite, репозиторий.
3.2 Валидация белорусского номера (нормализация `80…`/`+375…`, коды операторов) + подсказка на русском. Общий модуль для фронта и бэка.
3.3 Дедупликация: тот же номер в течение 10 минут → `200 {duplicate: true}`, новой записи нет; `client_request_id` закрывает двойной клик.
3.4 Источник заявки: `page_url`, `referrer`, `utm_*`, форма, вариант CTA.
3.5 Каркас FastAPI: CORS, `/healthz`, единый формат ошибок, rate-limit, структурные логи.
- **Результат:** `POST /api/lead` работает, заявка в SQLite, дубли не создаются.
- **Ключевой риск брифа:** сообщение об ошибке должно быть понятным пользователю, а не только кодом.

## Этап 4. Интеграция с телеграм-ботом (0,5 ч)
4.1 `GET /api/leads?after_id=&limit=` под `X-Admin-Token` — курсорная выдача для бота.
4.2 Согласование контракта с подпроектом `telegram-bot` (см. ../telegram-bot/README.md).
4.3 `scripts/seed_leads.py` — тестовые заявки без ручного заполнения формы.
- **Результат:** бот получает заявку в течение секунд после отправки формы.

## Этап 5. Тесты и качество (0,5 ч)
5.1 pytest: приём, дубль в окне, дубль после окна, не-белорусский номер, пропуски полей.
5.2 Vitest: двойной клик, ошибка сети, серверная ошибка; Playwright — happy path формы.
5.3 Ручной чек-лист: клавиатура, подписи для скринридера, `aria-invalid`, фокус на ошибке.
- **Результат:** зелёные тесты, список проверенных вручную сценариев.

## Этап 6. Деплой (0,5 ч)
6.1 Vercel: переменные `NEXT_PUBLIC_API_BASE_URL`, домен, HTTPS.
6.2 FastAPI: хостинг с постоянным диском под SQLite, CORS на домен Vercel.
6.3 Проверка живой формы с телефона, сценарий «API недоступен».
- **Результат:** сайт открывается по HTTPS, заявка с прода доходит до бота.

## Этап 7. Сдача (0,5 ч)
7.1 Lighthouse mobile (отчёт + скриншот), исправление провалов.
7.2 README 2–3 страницы: что сделано вручную / что ИИ; где ИИ ошибся и как замечено; что не успели.
7.3 Лог работы с ИИ: экспорт сессии, скриншоты ключевых моментов.
7.4 Коммиты по шагам, публичный репозиторий с доступом.
- **Результат:** комплект сдачи из раздела 05 брифа.
